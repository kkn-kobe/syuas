# 表デザイナーのUndo／Redo

## 実装状況

第1段階のCore層の状態保存・復元、第2段階のViewModelへの接続に加え、第3段階で画面の操作、連続入力の履歴、IME変換中の制御、フォーカス復元を実装しています。新規作成／再編集ともに、セル入力・属性変更・構造変更をデザイナー内で取り消し・再実行できます。

第4段階では、文書への挿入・適用、キャンセル、自動復元、外部変更との組み合わせを回帰テストへ追加し、利用説明とデザイナーから説明を開く操作を整備しました。

## 操作方法（第3段階）

- 「元に戻す」ボタン／Ctrl+Zで取り消し、「やり直し」ボタン／Ctrl+Y／Ctrl+Shift+Zで再実行します。ツールチップには次の操作名を表示します。
- 入力欄の右クリックにも同じUndo／Redoを用意しています。セルやタイトルの文字入力中、生成ソースの閲覧中も、表デザイナー全体の履歴を操作します。
- 同じセル・タイトル・列幅で続けて入力した文字は1件にまとめます。別の入力欄への移動、マウスや方向キー等でのカーソル操作、全選択、切り取り／貼り付け、IMEの開始・確定、表の構造変更で区切ります。時間経過だけでは区切りません。
- IME変換中はUndo／Redo・表の構造変更・ヘッダー変更・挿入／適用・キャンセルボタンを無効にします。Escapeは変換の取り消しに使えます。確定した文字列はまとめて取り消せます。変換を取り消して元の値に戻った場合は履歴を増やしません。
- Undo／Redo後は、操作時の入力欄・キャレット・文字の選択範囲と表の選択範囲を復元します。構造変更で入力欄がなくなった場合は表内の近い座標へ収め、結合セルの左上の入力欄を使います。列幅欄の復元時は折りたたみを開きます。
- 左下の「使い方」で、編集内容と履歴を保持したままオフラインの説明を開けます。IME変換中は無効です。説明はメイン画面の「ヘルプ → 表の再編集の使い方」と同じものです。

履歴はダイアログごとに独立し、閉じると破棄します。文書へ挿入・適用した表を、文書側で1回のUndoで戻す既存の動作も維持します。未適用の内容や履歴の永続化・自動復元は行いません。

## 状態の保存と復元

- `TableSnapshot.Capture(table)` は行列数、セルの座標・結合・本文、タイトル、ヘッダー、列幅を保存します。セルは座標順に並べ、読み取り専用コレクションと不変のセル値を保持します。元のモデルや復元先を変更しても保存状態は変わりません。
- `TableDefinition.Restore(snapshot)` は同じモデルのインスタンスへ復元します。既存表の再編集では `TableEditContext.Definition` が参照するモデルを維持できます。セルのインスタンスは作り直すため、ViewModelのセル参照は復元後に再構築する必要があります。
- `TableDesignerSnapshot.Capture(...)` は表の状態に加え、選択範囲、選択の起点、行数・列数の入力文字列、任意の `TableInputFocus` を保存します。入力文字列を省略すると、実際の表サイズを使用します。空欄や不正な数値文字列も保存できます。フォーカス情報はWPFコントロールを保持せず、入力欄の種類・座標・文字選択の位置と長さを記録します。
- 選択範囲は表内で結合セル全体を含み、起点は選択範囲内にある必要があります。選択だけの変化は内容の変更とは判定しません。

AsciiDocへの変換や再解析を経由しません。本文の空白・改行・文字参照と、列幅などの入力途中の値をそのまま保持します。履歴への保存では表構造を検証しますが、タイトルや列幅の記法としての妥当性は要求しません。nullの本文・タイトル・列幅は受け付けません。取り込み用の `TableDefinition.FromCells()` の厳密な検証は変更していません。

行数・列数の入力値と実際の表サイズは別の状態です。基盤は両方をそのまま復元します。ViewModelでの操作単位は次節のとおりです。

## ViewModelへの接続（第2段階）

`TableDesignerViewModel` がダイアログごとに履歴を所有します。既存の入力バインディングと各コマンドから、状態取得・変更・履歴記録・プレビュー更新を行います。`Definition` のインスタンスは維持し、履歴管理の開始後はセルや属性をViewModel経由で変更します。`Definition` を直接書き換えると、未記録変更として履歴操作を拒否する場合があります。

| 操作 | 現在の履歴単位 |
| --- | --- |
| 結合・解除・行列追加／削除・ヘッダー切り替え | 各操作で1件 |
| セル本文・表タイトル・列幅 | 画面では同じ欄の連続入力を1件にまとめる。入力セッション外からのプロパティ設定は変更ごとに1件。同じ値の再設定は記録しない |
| 行数・列数の入力からサイズ適用 | 途中に別の内容変更が入らなければ、入力開始前から適用後までを1件 |
| サイズ未適用のままUndo | 行数・列数の入力を1件として記録して取り消す。Redoで未適用の値も復元できる |
| サイズ入力後の別の内容変更 | サイズ入力を先に記録し、その後に別の変更を記録する |
| 範囲選択・選択移動 | 履歴は増やさず、Redoも維持する |

サイズ入力と連続した文字入力は、確定まで開始時点のスナップショットを1つ保持します。保留中も `CanUndo` は有効となり、`UndoCount` に1件を加えて表示します（IME変換中を除く）。`CanRedo` は無効です。入力を元の値に戻せば保留を解除し、既存のRedoを維持します。確定時に履歴基盤の件数・容量制限を適用します。

サイズ適用が失敗した場合は入力値を残し、修正またはUndoを続けられます。適用前にサイズ入力をUndo／Redoした場合や別の編集を挟んだ場合は、その入力が既に履歴へ確定しているため、後のサイズ変更のUndoで未適用の入力値へ戻る場合があります。

復元では表の状態に加え、選択範囲と起点、行列数入力を戻します。セル・列幅のViewModelを再構築し、生成ソース、挿入用Snippet、エラー、コマンドの実行可能状態を更新します。元の入力値が不正であれば、復元後も挿入／適用を無効にしてエラーを表示します。

通常のセル入力・タイトル・列幅・ヘッダー変更ではグリッド全体を再構築しません。Undo／Redoや構造変更・失敗後の復元で作り直した場合は、古いセル・列幅のバインディングから届く更新を無視します。復元処理中や適用コールバック実行中の再入操作も抑止します。

ViewModelは次のAPIを公開します。

- `UndoCommand` / `RedoCommand`: 表デザイナーの履歴を復元するコマンド。
- `CanUndo` / `CanRedo`、`UndoCount` / `RedoCount`: 保留中のサイズ入力・文字入力とIME状態も考慮した履歴状態。
- `UndoDescription` / `RedoDescription`: 次の履歴操作の説明。履歴がなければnull。
- `BeginTextEdit` / `UpdateInputFocus` / `EndTextEdit`: 入力セッションの開始、文字選択位置の更新、履歴の確定。
- `SetTextComposition`: IME変換状態の通知。変換中は構造・履歴操作を抑止し、編集中の入力欄の更新を受け付ける。
- `FocusRequested`: 履歴復元・構造変更後に、Viewへ入力欄の復元を依頼するイベント。

ViewはWPFのUndo／Redoルートコマンドをトンネル段階で受け取り、TextBoxより先に表全体の履歴へ送ります。履歴が空の場合も標準TextBoxのUndoへ流しません。IME処理のためTextBox内部のUndo機構は保持しますが、利用者が操作するボタン・キー・右クリックは同じ表の履歴を使います。IMEの開始／更新／完了イベントは処理済みイベントも受け取り、通常の直接入力（自動完了）と区別します。グリッド再構築後のフォーカス移動はDispatcher上で行い、復元によるフォーカスイベントで表の複数選択を崩さないようにします。

各変更後にプロパティ通知とコマンドの `CanExecuteChanged` を通知します。適用に失敗しても履歴を保持し、Undoで修正できます。デザイナー内の履歴操作では文書や文書のUndo履歴を変更せず、全変更を取り消してから適用すると既存の「変更なし」の処理を使用します。

## 履歴API

`TableEditHistory` は1つの `TableDefinition` に結び付け、モデルを所有するスレッドから使用します。WPF・AvalonEdit・ファイル保存に依存しません。

| API | 動作 |
| --- | --- |
| `Execute(description, before, change)` | 操作前の状態と実モデルを照合し、変更コールバックが返した操作後の状態を記録。例外時はモデルを操作前へ復元し、例外を再送出する |
| `Record(description, before, after)` | 呼び出し側が既に行った変更を記録。文字入力をまとめて記録するときなどに使う。拒否時は履歴を変えず、モデルの自動復元は行わない |
| `Undo()` / `Redo()` | モデルを復元し、選択・入力値の復元に使う `TableDesignerSnapshot` を返す。履歴がなければnull |
| `CanUndo` / `CanRedo` | 実行可能な履歴の有無。`Execute` の実行中はfalse |
| `UndoDescription` / `RedoDescription` | 次に取り消す／やり直す操作の表示名。該当する履歴がなければnull |
| `UndoCount` / `RedoCount` / `EstimatedBytes` | 履歴件数と推定保持容量 |
| `Clear()` | 履歴だけを破棄し、モデルの内容は維持する |

使用例（表全体を選択する最小例）：

```csharp
var table = new TableDefinition(2, 2);
var history = new TableEditHistory(table);

TableDesignerSnapshot Capture() => TableDesignerSnapshot.Capture(
    table, new TableSelection(0, 0, table.RowCount, table.ColumnCount), 0, 0);

history.Execute("セル結合", Capture(), () =>
{
    table.Merge(new TableSelection(0, 0, 2, 2));
    return Capture();
});

var restored = history.Undo(); // 同じtableへ結合前の状態を復元
// 呼び出し側はrestoredから選択・行列数入力を戻し、セル参照とプレビューを更新する。
history.Redo();
```

`Execute` の例外時にもセル参照の再構築が必要です。選択・入力文字列など呼び出し側の状態は、渡した `before` から戻してください。履歴操作には変更通知イベントを設けていないため、コマンドの有効状態やプレビューの更新も呼び出し側が行います。

## 履歴の整合性

- 変更なしの操作や選択だけの移動は記録せず、既存のRedo履歴を保持します。
- Undo後に新しい内容変更を記録すると、その先のRedo履歴を破棄します。
- 操作前の内容は履歴の現在位置と、操作後の表データは実モデルと一致する必要があります。Undo／Redoも復元前に実モデルを照合します。
- 記録されていない変更を検出すると例外を返します。入力中の変更は先に `Record` 等で確定してください。モデル外の行列数入力についても、Undo／Redo前に呼び出し側が確定する必要があります。
- 失敗した `Execute` は途中のモデル変更を取り消し、既存のUndo／Redo履歴を維持します。復元処理自体は履歴を増やしません。
- `Execute` 中の別の履歴操作は拒否します。履歴はダイアログの編集セッション内で使用し、永続化・自動復元は行いません。

## 履歴上限

既定値は100操作・推定32MiBです。コンストラクターで変更できます。UndoとRedoの合計を対象に、上限を超えた場合は古い操作から破棄します。

容量は各操作の前後の状態・操作名について、UTF-16文字数とオブジェクト分の概算から求めます。共有される文字列も重複して数える保守的な値であり、実測したヒープ使用量ではありません。

直近の1操作は必ず保持します。単独の操作が容量上限を超える場合は、他の履歴を破棄してその1操作を残すため、容量上限は厳密なメモリ制限ではありません。大きな表を削除した直後でも、1回のUndoで元に戻せます。

## 文書・復元・外部変更との統合（第4段階）

デザイナーでのUndo／Redoは文書へ書き込まず、「挿入」「適用」時に最終状態を反映します。「適用」はディスクへの保存ではありません。適用に失敗してもダイアログと履歴を残し、Undoで修正して再試行できます。失敗そのものは履歴を増やしません。

`TableCompatibilityTests` に実ファイル・実際のAvalonEdit・復元ストアを使う組み合わせを追加し、`TableDesignerLifecycleTests` で実際のWPFモーダルダイアログも確認します。

| 組み合わせ | 確認する内容 |
| --- | --- |
| 保存済み6サンプル × LF／CRLF × BOM有無 | 連続入力・行追加をUndo／Redoして適用。周囲の本文を保持し、文書のUndo 1回で適用前へ戻る。保存・再オープン後のデザイナー履歴は空 |
| 新規挿入・キャンセル・閉じる | デザイナー内の編集・Undo／Redoでは文書を変えない。挿入後は文書側の1回のUndo／Redoで復元。実際のキャンセルボタンでも文書を保持 |
| 適用失敗からの修正・再試行 | 対応外のセル本文で適用が失敗しても履歴を維持。Undo／Redo後の再試行またはキャンセルが可能 |
| 変更なしの適用・キャンセル × 文書の保存済み／未保存 | デザイナーで全変更をUndoして適用した場合も、文書のリビジョン・選択・保存基準・文書ID・未保存状態・既存Redoを保持 |
| デザイナー表示中の自動退避 | 未適用の編集やUndo／Redoを復元用コピーへ混入させず、文書側の内容だけを退避 |
| 適用後の退避・起動時復元 | 元ファイルの変更なし／外部変更／削除を確認。復元した表を再編集してUndo／Redoでき、保存時の競合チェックも維持 |
| 文書のUndo／Redoと復元コピー | 保存済み状態へUndoするとコピーを整理。Redoで未保存状態へ戻すと次の退避で適用済みの内容を保存 |
| 外部変更中の適用・キャンセル | デザイナーや文書のUndo／Redoで保存基準を更新しない。通知を閉じても保存前に再検査し、キャンセル・別名保存・バックアップ付き上書きを使う |
| デザイナーからの利用説明 | 埋め込み説明を開いて閉じても編集と履歴を保持し、その後もUndoできる |

復元はサービスを破棄して作り直す方法で検証します。実プロセスの強制終了テストではありません。外部変更はテスト専用ファイルへ書き込み、検査を明示実行します。利用説明の原文は [表の作成・再編集の使い方](table-reediting-guide.txt) です。
