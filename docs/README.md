# SYUAS

AsciiDocソースを直接編集するWindowsデスクトップエディタです。基本編集、記法のGUI入力補助、表の作成・再編集、文書構造表示、HTMLプレビュー、自動復元、外部変更検出を備えています。

[AGENTS.md](AGENTS.md) は当初の要件と開発優先順位です。現在の機能・対応範囲はこのREADMEと以下のドキュメントを参照してください。表の再編集は現在のSYUASの生成形式に限定して対応しています。

## 開発・起動

対象OSはWindows 11です。開発には.NET 8をターゲットにビルドできる.NET SDK、アプリの実行には.NET 8 Desktop Runtimeが必要です。初回のパッケージ復元にはNuGetへの接続が必要です。

HTMLプレビューにはMicrosoft Edge WebView2 Runtimeも必要です（Windows 11では通常導入済み）。未導入の場合でもソース編集は使用でき、プレビュー欄にエラーを表示します。導入後はSYUASを再起動してください。Asciidoctor.jsはアプリに同梱しており、Node.jsやRubyのインストールは不要です。

```powershell
dotnet restore SYUAS.sln
dotnet build SYUAS.sln --no-restore
dotnet test SYUAS.sln --no-restore
dotnet run --project src/Syuas.App/Syuas.App.csproj --no-restore
```

Visual Studioからは `SYUAS.sln` を開き、`Syuas.App`をスタートアッププロジェクトに指定します。

## 基本編集とファイル操作

- AvalonEditによるソース編集、行番号、Tab入力、複数行選択、コピー・切り取り・貼り付け、全選択。
- 新規作成、開く、保存、名前を付けて保存。対応拡張子は `.adoc` / `.asciidoc` / `.ad` / `.asc` / `.txt`。
- 最近使用したファイル（最大10件）と1ファイルのドラッグ＆ドロップによるオープン。
- 未保存表示と、新規作成・別ファイルを開く・終了時の保存確認。保存失敗やキャンセル時は編集内容を保持。
- Undo / Redo。保存した履歴位置までUndo / Redoすると未保存表示も解除。
- 文字列検索、先頭への折り返し、大文字小文字の区別、選択箇所の置換、すべて置換。すべて置換は1回のUndoで取り消し。
- カーソル行・列、UTF-8表示、行番号の表示切り替え、折り返し表示。
- 見出し、ブロック区切り、属性、include / image / link / xref、URL、Admonition、コメント、ソースブロックの簡易ハイライト。

| 操作 | ショートカット |
| --- | --- |
| 新規 / 開く / 保存 | Ctrl+N / Ctrl+O / Ctrl+S |
| 名前を付けて保存 | Ctrl+Shift+S |
| Undo / Redo | Ctrl+Z / Ctrl+Y |
| 検索 / 置換 | Ctrl+F / Ctrl+H |
| 次を検索 | F3（検索欄ではEnterも可） |
| 検索欄を閉じる | Escape |

置換は選択中の文字列が検索文字列と一致するときに実行し、次の一致箇所を選択します。一致しない場合は検索のみ行います。検索は正規表現ではなく文字列検索です。

UTF-8（BOM有無の両方）を読み込み、BOMなしUTF-8で保存します。既存の改行は維持します。UTF-8でないファイルは文字化けした状態で保存しないよう読み込みエラーにします。保存は同じフォルダーの一時ファイルに書き込んでから置き換えます。

最近使用したファイルは `%LOCALAPPDATA%/SYUAS/recent-files.json` に保存します。履歴ファイルが壊れている場合は空の履歴から起動します。履歴の保存失敗は文書の保存結果に影響しません。

## 記法の入力補助

「挿入」「書式」メニューとツールバーから使用します。ダイアログの生成結果は入力に合わせて更新され、不正な値がある場合は挿入できません。

| 機能 | 動作 |
| --- | --- |
| 見出し | Level 1〜5を選択（`==`〜`======`）。現在行の文字列を取り込み、既存の見出しレベルも変更可能 |
| 画像 | ファイル参照、Block / Inline、Alt Text、Title、Width、Height、ID、相対 / 絶対パス |
| Include | ファイル参照、相対 / 絶対パス。詳細設定でlines・tag・leveloffset・tags・indent・encoding・optionalを指定 |
| Link / xref / Anchor | URLや参照先、表示文字列、IDを入力。xrefは文書内候補から選択可能。Anchorは重複しないIDを提案 |
| Source Block | 選択文字列を取り込み、言語を選択または自由入力。C#はcsharp、C++はcppへ変換 |
| Admonition | NOTE / TIP / IMPORTANT / CAUTION / WARNING。複数行はブロック形式、単一行でもブロック形式を指定可能 |
| List | 箇条書き・番号付き・チェックリスト。現在行または選択範囲に含まれる行全体へ適用 |
| Inline Format | Bold / Italic / Monospace。未選択なら空の記号対を挿入し、中央へカーソルを配置 |
| その他のBlock | Listing / Literal / Quote / Example。選択文字列を囲み、未選択なら空ブロックを挿入 |

ダイアログのキャンセルは文書を変更しません。各入力補助は1回のUndoで取り消せます。ブロック挿入時には前後の本文との間に必要な空行を補い、文書のLF / CRLFを引き継ぎます（改行のない新規文書はWindowsのCRLF）。既存テキスト内に区切り行がある場合は、外側の区切りを長くして衝突を避けます。

画像・includeの相対パスは保存済み文書のフォルダーが基準です。文書が未保存、または別ドライブのファイルの場合は絶対パスを生成します。未保存文書で相対パスを使う場合は、先に文書を保存してください。挿入ダイアログのパス生成では、画像の `imagesdir` 属性やincludeで変更された属性などを解析しないため、そのような文書では生成後のパスを必要に応じて調整してください。HTMLプレビュー側は `imagesdir` に対応しますが、参照範囲は文書フォルダー配下に限られます。生成できるパスとプレビューで読み込めるパスの範囲は異なります。

## 表デザイナーでの新規作成

「挿入 → 表」またはツールバーの「表」から開きます。初期値は3行×3列、ヘッダーなしです。

1. 行数・列数を入力して「サイズを適用」を押します。最大100行×50列で、行数はヘッダー行を含みます。
2. 必要に応じて表タイトル、ヘッダー、列幅を指定します。列幅は比率（例: 1 / 2 / 1）で、空欄は1です。
3. セル内で文章を編集します。Enterでセル内に改行を入力できます。
4. セルをクリックし、Shift＋クリックで範囲を選択して「セル結合」を押します。結合済みセルをまたぐ選択は、そのセル全体まで自動で広がります。
5. 右側のAsciiDocプレビューを確認し、「挿入」を押します。表全体の挿入は1回のUndoで取り消せます。

「結合解除」は選択範囲内の結合セルを解除します。結合時は文章を行・列順に改行でまとめ、解除時は左上のセルにその文章を残します。ヘッダーと本文をまたぐ縦結合はできません。

「下に行追加」「右に列追加」は選択範囲の直後に追加します。「行削除」「列削除」は選択範囲の先頭行・列が対象です。サイズ縮小は下端・右端から削除します。削除対象だけに属する文章は削除され、結合セルが一部残る場合は文章と残りの結合範囲を保持します。編集中の表を破棄するときは「キャンセル」で文書を変更せずに戻れます。

出力時には列数・結合数を自動計算し、`2+|`、`.3+|`、`2.3+|`などの記法を生成します。ヘッダー設定は `options="header"` / `options="noheader"` として明示し、意図しない自動ヘッダー判定を防ぎます。セルの `|` とその直前のバックスラッシュは文字参照に変換して、別のセルや表の終端として解釈されないようにします。

既存の表は「編集 → 表を再編集…」または右クリックメニューから、同じデザイナーで修正できます。対象は現在のSYUASが生成する形式の表です。header／noheader指定のない表、1行に複数セルを書く表、追加属性・セルスタイル・includeを含む表などは対象外です。詳しくは [表の再編集の使い方](docs/table-reediting-guide.txt) を参照してください。

デザイナー内では「元に戻す」「やり直し」ボタン、Ctrl+Z／Ctrl+Y／Ctrl+Shift+Z、入力欄の右クリックから、セル入力・属性変更・結合・行列操作をUndo／Redoできます。同じ入力欄の連続入力はまとめて取り消し、入力欄の移動・カーソル操作・切り取り／貼り付け・IME確定などで区切ります。Undo／Redo後は入力欄と文字の選択位置も復元します。IME変換中はUndo／Redo・構造変更・挿入／適用を無効にし、確定後に操作できます。

文書へ挿入・適用した変更は、文書側で1回のUndoで取り消せます。デザイナーの履歴はダイアログ内だけで保持し、未適用の変更は自動復元の対象に入りません。詳細は [表デザイナーのUndo／Redo](docs/table-designer-history.md) を参照してください。

結合をUndoすると、結合前の各セルに元の文章が戻ります。「結合解除」は文章を左上セルへ残して分割する操作です。Undo後に別の編集を確定するとRedoは破棄されます。履歴は通常100操作・推定32MiBまでで、超えた分は古いものから失われます（直近の1操作は保持）。全修正を破棄する場合は「キャンセル」を使います。具体的な手順は、デザイナーの「使い方」で確認できます。

## 表の再編集

表の中にカーソルを置くか、1つの表の中を選択し、「編集 → 表を再編集…」または右クリックメニューの「表を再編集…」を選びます。既存の内容・結合・列幅・ヘッダーを読み込んだデザイナーで修正し、「適用」で元の表へ反映できます。新規作成は引き続き「挿入 → 表…」を使います。

キャンセルや変更なしの適用では文書と履歴を変更しません。反映は1回のUndoで戻せます。対象外の表には理由と場所を案内し、適用に失敗した場合はダイアログ内に理由を表示して入力内容を保持します。セル内の文字参照はソースの表記を維持します。

`AsciiDocTableParser.Parse()` で現在のSYUASの生成形式を `TableDefinition` へ読み戻せます。タイトル・列幅・ヘッダー・結合・複数行セルを復元し、再生成したソースとの完全一致を確認します。未対応形式や不正な結合には、日本語の理由と行・列番号を返します。モデル構築には、入力をコピーして構造を検証する `TableDefinition.FromCells()` を使用します。

`AsciiDocTableLocator` がカーソル・選択範囲から対象表を特定し、`TableEditingService` が文書ID・本文リビジョン・元ソースを照合して置換します。周囲の文章、独立したAnchor、終了区切り直後の改行を維持し、表の更新を1回のUndo／Redoで戻せます。キャンセルや変更なしの適用では文書と履歴を変更しません。コード例・複合ブロックなどの対象外の表や、区切りを確定できない表には理由を返します。

保存済みサンプルによる互換性テスト、Asciidoctor.jsによるHTMLの照合、保存・復元・外部変更との統合検証を用意しています。実WebView2によるHTML照合は、検証手順にある環境変数を指定して実行します。「ヘルプ → 表の再編集の使い方」から、操作方法・対応外の形式・保存と復元の注意点をオフラインで確認できます。

対応範囲とAPIは [表の再編集](docs/table-reediting.md)、検証内容と再実行手順は [表の互換性検証](docs/table-compatibility-validation.md)、保存済みの表は [サンプル一覧](samples/table-reediting/README.md) を参照してください。

## 文書構造・参照とHTMLプレビュー

### 文書構造と参照候補

左側のDocument Outlineに見出しを階層表示します。クリックするとその行へ移動します。編集後約450msで更新し、「表示 → 文書構造」で表示を切り替えられます。

「挿入 → 相互参照」の候補一覧から見出し・アンカーを選択するとTargetを入力します。表示文字列が空なら見出し名も設定します。Targetの自由入力は引き続き可能です。「アンカー / ID」では選択文章や近くの見出しから新しいIDを提案し、既存IDの重複を検出します。

簡易解析の対象は `=`〜`======` の見出し、`[[id]]`、`[#id]`、`[id="id"]`、見出し末尾の `[[id]]`、一般的な自動IDです。コード・コメント・表などの区切りブロック内は除外します。`idprefix` / `idseparator` / `sectids`にも対応します。include先や条件分岐、属性置換、複雑なインライン書式の完全解析は行わないため、そのような文書では実際の参照先を確認してください。

### 高度なinclude設定

詳細設定で `tags`（例: `intro;usage` / `**;!internal`）、`indent`（0以上）、`encoding`（自由入力可）、`optional`（`opts=optional`）を指定できます。`lines`・`tag`・`tags`はどれか1つだけ指定します。従来の`leveloffset`とも組み合わせられます。

### HTMLプレビュー

「表示 → HTMLプレビュー」またはツールバーで、ソース右側に分割表示します。保存前の編集内容も反映します。変換は同梱Asciidoctor.jsが行い、独自のHTML変換エンジンは使用していません。連続編集中は古い変換結果を破棄し、最新内容を表示します。

保存済み文書では、文書フォルダー内の相対パスによるinclude・画像（`imagesdir`を含む）に対応します。include先の編集など外部ファイルの変更を反映するときは「表示 → プレビューを更新」を押してください。文書内リンクはプレビュー内で移動できます。

プレビューの参照範囲は文書フォルダーとその配下です。親フォルダー・別ドライブ・絶対ファイルパス・シンボリックリンクを経由した参照とリモートURLは読み込みません。未保存文書ではincludeを展開しません。1リソースは16MBまで、includeのネストは10段までです。文書内のスクリプトやフォーム送信、外部リンクへの移動は無効です。HTML/PDFファイルの書き出しは実装していません。

## 文書状態とファイル照合の仕組み

文書状態とファイル照合を、保存前チェック、自動退避・起動時復元、常時監視・通知・比較・再読み込みで共有しています。

- `DocumentSession` は文書ID、編集リビジョン、最後の読み込み／保存時のリビジョン、保存基準、未保存状態を保持する不変のスナップショットです。新規作成・ファイルオープンで文書IDを新しくし、保存・名前を付けて保存では維持します。
- `DocumentSessionController` がエディタとファイルサービスを仲介します。読み込み／保存に成功した場合だけ保存基準を更新します。読み込み失敗時は本文・Undo履歴・セッションを維持します。確認ダイアログは引き続き `MainViewModel` が担当します。
- `IEditorAdapter.ContentChanged` は本文の変更通知です。`ContentRevision` はエディタの存続中に単調増加し、本文が変わるUndo・Redo・読み込みも含みます。カーソル移動・選択・保存済みマークの変更では増加しません。文書を識別するときは文書IDとリビジョンを組み合わせます。
- `SavedRevision` と現在リビジョンの差は未保存判定に使用しません。Undoで保存位置へ戻った場合もリビジョンは進むため、未保存状態はAvalonEditの保存位置判定を使用します。
- `IFileService.ReadSnapshot()` は一度読み取ったバイト列から本文とSHA-256を生成します。UTF-8のBOMは本文から除きますが、照合用ハッシュには含めます。改行の違いも検出します。
- `WriteSnapshot()` は実際に書き込むBOMなしUTF-8のバイト列から保存基準を生成し、一時ファイルからの置換に成功した後に返します。保存後の再読み込みで外部更新を誤って保存基準へ取り込まない構成です。
- `Compare()` は基準ファイルの全内容を照合し、`Unchanged`／`Modified`／`Missing`／`Unavailable` を返します。更新日時には依存せず、同じサイズの変更も検出します。ロックやアクセス拒否を削除扱いにせず、外部で不正UTF-8へ変更された場合も内容変更として検出します。照合だけでは保存基準を更新しません。

通常のファイルオープン・再読み込み・保存前照合・明示的な保存は同期処理で、Controllerはエディタを所有するスレッドから呼び出します。低速な共有フォルダーや大きな文書では待ち時間が発生します。自動退避・復元データの読み書き、監視用の照合、比較画面用の読み込みはバックグラウンドで行います。

## 保存前の外部変更チェック

Ctrl+S、名前を付けて保存、終了・新規作成・別ファイルを開く際に選んだ「保存」で、保存先を照合します。編集していない文書でも明示的に保存した場合は確認します。

| 保存先の状態 | 操作 |
| --- | --- |
| 最後に開いた／保存した内容と同じ | 通常どおり保存 |
| 外部で内容が変更された | 別名保存／外部版を退避して上書き／キャンセル |
| 元ファイルが削除・移動された | 別名保存／元の場所に再作成／キャンセル |
| ロック・アクセス拒否などで確認できない | 別名保存／再試行／キャンセル |
| 別名保存先に既存ファイルがある | 別名保存／外部版を退避して上書き／キャンセル |

確認画面には保存先の絶対パスを表示し、初期フォーカスと既定ボタンはキャンセルです。Escapeでもキャンセルできます。ファイル選択画面の既定の上書き確認に代わり、この画面で実際に照合した版への上書きを確認します。同じパスを「名前を付けて保存」で選んだ場合も、現在の文書の保存基準を使用します。

承認した後も、出力を準備して置き換える直前に再照合します。確認中に再変更された、削除された、再作成された場合は改めて判断を求めます。「再試行」は上書き許可として扱いません。キャンセル・保存失敗時は本文、Undo履歴、文書ID、保存基準、最近使用したファイルを維持します。

上書き時の退避ファイルは、保存先と同じフォルダーの `.元ファイル名.syuas-backup.UTC日時.識別子.bak` です。元のバイト列をそのまま保持し、BOMや不正なUTF-8も変更しません。保存成功後の案内に退避先を表示します。必要に応じてこのファイルを別名でコピーして内容を回収できます。退避ファイルは自動削除しません。

文書保存は `WriteChecked()` を使用します。既存ファイルの置換には `File.Replace` のバックアップ機能を使い、退避できない場合は上書きを中止します。通常保存でも置換時点の元ファイルを一時的に退避し、確認した内容と一致した場合だけ削除します。最終照合と置換の短い間に外部変更が起きた場合や、退避ファイルの照合・削除ができない場合は退避を残して保存後に場所を通知します。新規作成・再作成は上書きしない移動処理を使い、直前に現れたファイルを置き換えません。

他アプリとの完全な排他保存を保証するものではありません。置換直後に別アプリが再保存した変更は、常時監視および次回保存時の照合対象になります。保存基準はSYUASが書き込んだ内容から生成し、後から現れた外部版を保存済みとして採用しません。

## 自動退避と起動時復元

自動復元は起動時に有効になります。未保存の変更がある文書は、入力停止から約5秒後、入力を続けている場合は約30秒ごとを目安に復元用コピーへ退避します。無題の文書や、本文をすべて削除した未保存文書も対象です。元ファイルへの自動上書きは行いません。カーソル移動・選択範囲の変更だけでは退避しません。

保存先は `%LOCALAPPDATA%\SYUAS\Recovery\セッションID\` です。文書ごとに最新と直前の2世代を保持します。UTF-8のJSONに、本文・文書ID・リビジョン・退避日時・元ファイルの保存基準・選択範囲・カーソル位置を保存し、本文とメタデータ全体のSHA-256で破損を検出します。

異常終了などで復元用コピーが残っている場合、次回起動時に「復元可能な文書」を表示します。文書名、退避日時、元ファイルの状態を確認して、次の操作を選べます。

| 操作 | 動作 |
| --- | --- |
| 復元する | 選択した1件を未保存状態で開く。保存するまでは復元用コピーを保持 |
| 後で | 候補を保持したまま編集画面に戻る |
| 破棄する | 確認後、選択した候補の復元用コピーを破棄。元ファイルは変更しない |

「ファイル → 復元可能な文書」から後で一覧を開けます。複数候補は1件ずつ復元でき、未選択の候補は残ります。候補を日数だけで自動削除することはありません。

最新世代が破損している場合は直前の世代を使用し、その旨を表示します。両方とも読めない候補は「復元不可」として残し、他の候補を引き続き復元できます。復元しただけではデータを削除しないため、復元直後に再度異常終了しても再復元できます。以前のUndo履歴は復元せず、復元後の編集から新しい履歴を作ります。

元ファイルのパスと退避時の保存基準を維持します。元ファイルが外部で変更・削除されていても本文を復元でき、その後の保存で外部変更の競合確認が働きます。復元時点のディスク内容を新しい保存基準として採用することはありません。

通常保存の成功、Undoで保存済み状態へ戻った場合、文書を破棄して切り替えた場合、保存／破棄を確認して終了した場合には、該当する復元用コピーを整理します。開く・保存の失敗やキャンセルでは現在のコピーを保持します。切り替え先の読み込みが失敗した場合も現在の編集内容とコピーは残ります。

`RecoveryService` がUIスレッドで変更タイミングを管理し、本文を取得してから不変のスナップショットをワーカーへ渡します。書き込み・整理・候補の取得は同じキューで直列化し、遅れて完了した退避が保存済み文書のデータを再作成しないようにしています。ファイルの書き込みは一時ファイルをフラッシュしてから置換します。整理時には本文を含まない終了記録を先に確定し、後始末が中断しても古い世代を復元候補にしません。

セッションごとに排他ロックを保持します。他のSYUASで編集中のデータは候補から除外し、復元・破棄の直前にもロックを確認します。復元時は現在のセッションにコピーを確定してから元の候補を整理します。

退避に失敗しても編集は継続でき、前回成功したコピーを残してステータスバーにエラーを表示します。変更がなくても失敗した退避を再試行します。起動時に復元フォルダーを開けない場合も編集機能は使えます。復元できるのは最後に正常に退避できた時点までで、約5秒／30秒は処理負荷・ディスクの状態によって前後します。

## 常時監視と通知・比較・再読み込み

現在編集中のファイルを監視し、元ファイルが外部で変更・削除された場合や状態を読み取れない場合に、エディタ上部へ通知バーを表示します。未編集の文書でも自動では読み込み直しません。本文・選択範囲・Undo履歴・保存基準を保持して利用者の操作を待ちます。

| 操作 | 動作 |
| --- | --- |
| 内容を比較 | 編集中のソースとディスクから取得したソースを、読み取り専用で左右に表示 |
| 再読み込み | 未保存の変更を保存／破棄／キャンセルで確認し、ディスクの最新内容を読み込み |
| 別名保存 | 編集内容を別ファイルへ保存。既存の保存先には保存前の競合確認を適用 |
| 再確認 | ディスクの状態をもう一度照合 |
| 編集を続ける | その状態の通知バーを閉じ、編集を継続 |

通知を閉じても外部変更の記録と保存基準は維持します。ステータスバーの「外部変更あり」「元ファイルなし」「確認不能」から通知を再表示できます。同じ状態の重複通知ではバーを再表示せず、別の外部版が検出された場合には改めて表示します。元の内容へ戻った場合や、保存・再読み込みに成功した場合は通知を解除します。

「ファイル → 外部変更を確認」「ディスクから再読み込み」「ディスク上の内容と比較」からも操作できます。比較画面は取得時点の2つのソースを表示し、行番号・簡易ハイライト・コピーに対応します。開き直すと最新のディスク内容を取得します。比較しただけでは編集内容や保存基準を変えません。行単位の差分強調と自動マージは今後の拡張対象です。

再読み込みはファイルの読み取りとUTF-8の検証が成功してから文書を入れ替えます。失敗やキャンセルではその時点の文書と復元用コピーを保持します。成功時はUndo履歴をリセットし、カーソル位置を新しい本文の範囲内へ収めます。確認で別名保存した場合は編集内容を別ファイルへ残し、最初に再読み込みを指定した元ファイルを開き直します。

`FileSystemChangeMonitor` は親フォルダーの更新・作成・削除・名前変更を監視し、対象パスに関係するイベントだけを通知します。一時ファイルからの置き換えによる保存にも対応します。`ExternalChangeService` は約500msの連続イベントをまとめてバックグラウンドでSHA-256を照合します。イベントが続いても約2秒で一度確認し、さらに10秒ごとの定期照合とウィンドウの再アクティブ化時の照合で通知の欠落を補います。削除・読み取り不能は短い間隔で再試行してから通知します。

監視エラー時は監視の再開を試み、開始できない間も定期照合を継続してステータスバーへ表示します。元フォルダーが削除され、後から再作成された場合も監視を再設定します。新規作成・ファイル切り替え・別名保存・復元・再読み込みでは監視先や照合の世代を切り替え、古い非同期結果を適用しません。終了時はタイマーと監視を停止します。

SYUAS自身の保存通知も内容で照合し、時間だけで通知を無視する方式は使いません。監視と明示的な保存は同じファイルサービスを共有してI/Oを調整し、バックグラウンドの読み取りが自分自身の保存と競合することを防ぎます。定期照合のハッシュ計算はストリームで行います。通知を閉じた場合や監視機能が使えない場合でも、保存直前の競合確認は独立して継続します。

監視対象は現在の文書です。include先・画像の変更によるプレビュー自動更新は対象外です。共有フォルダーの遅延や連続した外部更新などによって検出時刻は前後します。

## 障害時の検証と利用説明

退避の書き込み・置換・整理・復元途中の失敗、監視のI/O例外、保存や文書切り替えとの競合を回帰テストで確認します。整理できなかった復元用コピーは確認済みの終了時に再試行し、残る場合は次回に再表示される可能性を案内します。

強制終了と複数プロセスの検証は次のコマンドで実行できます。利用者の復元データには触れず、テスト用の子プロセスと一時フォルダーを使います。

```powershell
dotnet run --project tests/Syuas.RecoveryProbe/Syuas.RecoveryProbe.csproj --no-restore
```

詳細な障害シナリオ、実施結果、未検証の環境条件は [障害検証](docs/failure-validation.md) を参照してください。[利用説明](docs/recovery-guide.txt) はアプリに埋め込むため、配布後もヘルプから参照できます。

## 構成

- `src/Syuas.Core`: エディタ非依存のモデル・Generator、表のParser・Locator・再編集サービス、ViewModel、文書状態、ファイル操作、復元、外部変更監視、履歴、検索、挿入範囲・改行・カーソル位置の制御。
- `src/Syuas.App`: WPF View、Windowsダイアログ、入力フォーム、AvalonEdit Adapter、埋め込みXSHD、WebView2、同梱プレビューエンジン。
- `tests/Syuas.Tests`: ファイル・検索・文書ライフサイクル、記法生成、表の解析・再編集・互換性、復元・外部変更、入力検証、実際のAvalonEditでの挿入・Undo、WPF画面・ダイアログの読み込みとバインディングのテスト。Windows上で実行します。
- `tests/Syuas.RecoveryProbe`: 子プロセスを使用した強制終了・再復元・排他の検証ツール。
- `docs`: 表の再編集と自動復元・外部変更の利用説明、設計、互換性・障害検証手順と実施記録。
- `samples`: 基本編集・入力補助・プレビュー用の文書と、表の再編集の対応／対応外サンプル。

表の構造は `TableDefinition` / `TableCell` が管理し、`AsciiDocTableGenerator` はWPFに依存しません。テストでは2×2表、100×50表、ヘッダー、列幅、縦横結合、結合範囲の追加削除、特殊文字、混合操作後のセル範囲整合性を検証します。

AvalonEditへの直接参照はAppに閉じ込めています。各Generatorはモデルから文字列を生成し、`EditorInsertionService` が `IEditorAdapter.BeginUpdate()` と `Replace()` で1回のUndoにまとまる編集を行います。テストはApp経由で実際のAvalonEditも検証します。

ハイライト・文書構造抽出は簡易ルールで、AsciiDocの完全な解析や埋め込み言語の構文解析は行いません。

通常のテストに加えて実WebView2の統合確認を実行する場合は、以下を使用します。テストは透明な非アクティブウィンドウで実行し、include・画像・更新順序・スクリプト無効化を検証します。結果のHTMLとPNGを指定フォルダーへ保存します。

```powershell
$env:SYUAS_WEBVIEW_SMOKE = Join-Path $PWD '.local/webview-fixtures'
dotnet test SYUAS.sln --filter FullyQualifiedName~WindowTests
Remove-Item Env:SYUAS_WEBVIEW_SMOKE
```

## 手動確認

1. 新規文書に日本語と見出しを入力し、`.adoc` として保存・再オープンする。
2. 変更後の新規作成・オープン・終了で、保存 / 破棄 / キャンセルをそれぞれ確認する。
3. 検索と置換、すべて置換のUndo、保存位置までのUndo / Redoを確認する。
4. `.adoc` をエディタへドロップし、アプリを再起動して最近使用したファイルから開く。
5. `samples/phase1.adoc` でハイライト、Tab入力、コピー・貼り付け、行・列表示を確認する。
6. `samples/phase2.adoc` の文章を選択して見出し・リスト・書式・ソースブロックを適用し、Ctrl+Zで戻す。
7. 保存済み文書から画像・includeの参照ボタンでファイルを選び、相対パスと生成結果を確認する。未保存文書では絶対パスになることも確認する。
8. 空のリンク表示文字列・空のソースブロックを挿入し、カーソル位置を確認する。入力ダイアログのキャンセルで文書が変わらないことを確認する。
9. 表デザイナーで4行×4列・ヘッダーありの表を作り、本文の2列×3行を結合する。セル編集・行列追加削除・結合解除と、デザイナー内のボタン／Ctrl+Z／Ctrl+Y／Ctrl+Shift+ZでのUndo／Redoを確認する。日本語IMEの変換・確定・取消、入力欄と文字選択の復元、挿入後の文書側のUndoも確認する。
10. `samples/phase3.adoc` で各種セル結合のAsciiDoc出力例を確認する。
11. `samples/phase4.adoc` を開き、アウトラインから移動、xref候補の選択、重複しないAnchor候補を確認する。
12. HTMLプレビューを開いてソースを編集し、include先とSVG画像が表示されることを確認する。外部ファイルを変更した場合は「プレビューを更新」を押す。
13. 同じ文書を別のエディタで変更してからSYUASで保存し、キャンセル・別名保存・退避して上書きを確認する。退避ファイルの内容が外部版と一致することを確認する。
14. 元ファイルを削除してから保存し、再作成を確認する。確認画面を開いたまま別エディタでさらに変更してから上書きを選び、再確認が表示されることを確認する。
15. テスト用の無題文書を編集し、ステータスバーに復元用コピーの時刻が出てからプロセスを強制終了する。再起動して本文と未保存状態を復元できることを確認する。
16. 復元一覧で「後で」を選び、「ファイル → 復元可能な文書」から再度開く。復元後に保存せず強制終了しても再復元できることを確認する。
17. SYUASを2つ起動し、片方で編集中の文書がもう片方の復元一覧に出ないことを確認する。
18. 別のエディタで元ファイルを変更し、通知バーが出てもSYUASの本文が変わらないこと、比較画面で両方の内容を確認できることを確かめる。
19. 「編集を続ける」で通知を閉じ、保存時には競合確認が出ること、さらに別の外部変更があると通知が再表示されることを確かめる。
20. 未保存状態で再読み込みを選び、キャンセル時は本文・Undoを保持し、破棄して再読み込みした場合は最新の本文へ切り替わることを確かめる。
21. `samples/table-reediting/basic.adoc` を開き、表の中にカーソルを置いて「編集 → 表を再編集…」を実行する。セルを修正して適用し、1回のUndo／Redoで表全体の変更を取り消し・再実行できることを確認する。
22. 同じ表を再編集し、キャンセル・変更なしの適用で本文や未保存状態が変わらないことを確認する。右クリックメニューからも開けることを確認する。
23. `samples/table-reediting/unsupported/` の表では、再編集できない理由と位置を表示し、元のソースが変わらないことを確認する。
